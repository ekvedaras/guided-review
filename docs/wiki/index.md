# Wiki

Notes for agents and people who work on this repo: decisions, the reasons behind them, and what is known to be open. Plans and tickets live in GitHub issues, not here. Each page is dated, so check the commit a claim cites before you trust it. The rules themselves are in [CODING_STANDARDS.md](../../CODING_STANDARDS.md) and [AGENTS.md](../../AGENTS.md); the wiki cites them and does not repeat them.

A page states each decision once, in its current form. When a decision changes, edit it in place and keep the reason for the change in one sentence; do not append a later entry that supersedes an earlier one.

- [Panic and error policy](panic-policy.md): `unwrap`, `expect` and `panic!` are denied in `src/`; a true invariant keeps an `expect` only under `#[expect(..., reason)]`; tests may panic.
- [Where work is tracked](delivery.md): plans and tickets live in GitHub issues; the project is public with a private archive repo and signed commits; each spec lands as small commits on `main` or as one PR.
- [Agents the app works with](agent-runs.md): herdr is required and agents run in `auto` mode; how a subject's agent is found and picked; Refresh tour handed to the tour agent, with Cancel; hand-offs (the agent may change the PR's code, someone else's comments, hidden text); where the review agent works; one window; the agent link; a command never quits an app of another build.
- [Agent threads](agent-threads.md): the 2026-11-27 removal of the Ask panel; Ask agent as a private thread kept in the state file; Comment and ask agent keeps the old config names; a trial build names its full path to agents.
- [Agent builds and the maintainer's machine](agent-builds.md): after the 2026-11-17 overload, one agent builds at a time, `target/` is shared and never wiped mid-build, and the full gate runs once at the end.
- [Tests seen red first](red-first.md): `scripts/red` records a red run in the git directory, `scripts/check` warns about added tests with none, and test data uses invented names.
- [Rust quality audit, 2026-11](rust-audit-2026-11.md): the 2026-11-04 lint set and the pedantic lints left off, the reviewed exceptions, the one problems list for user-facing errors, render-cost rules, domain types, and the decisions on `#` in piece ids, `FilePath` and the single-crate check loop.
- [Deepening pass](deepening-pass.md): the 2026-11-12 rules that put decision logic in the viewer (the `SavedState` gate, `Problems`, `CommentDesk` text boxes, the kept `Page`, the work agenda, `Intent`/`Effect` `decide`), and the behaviour questions still open.
- [Second deepening pass](deepening-pass-2.md): the 2026-11-17 rules that give one owner to each rule spread over builders (`ReviewBuilder`, `ReplacingJobs`, `BranchLink`, `PrControls`, `OpenedSubject`) and a re-pin that moves the ref last, with the behaviour questions still open.
- [deslop-please](deslop-please.md): the module-structure linter in the gate, why it checks all features and keeps one allow list per target, the rules for fixing its errors, and why each remaining allow-list entry stays.
- [Platform](platform.md): the 2026-11-14 seam for what differs by OS: one platform module with one adapter per OS, `target_os` kept in it by the gate, a release Target that is an OS and a CPU, the Primary modifier, fonts, the Desktop entry, XDG app folders, and the Linux CI and release.
- [Updates](updates.md): the 2026-11-11 one-click update; only a release install updates itself; an update moves links and never writes over the binary; Guided Review.app; a `guided-review` earlier on `PATH` is a problem; when the app checks; restart runs the new binary by full path.
- [Code host capabilities](code-host-capabilities.md): `CodeHost` as core ports plus optional ones, why an optional port and not a flag list, `HostCapabilities`, the host contract run against the fake and GitHub, `HostSite`, `HostedRepo` and where each is keyed, and what stays GitHub's on purpose.
- [GitHub outage](github-outage.md): a server error, a timeout or no connection is one outage with one problem and one toast that closes by itself, read again with backoff until GitHub answers.
- [PR notes](pr-notes.md): buttons that put a diagram, a summary picture or the summary in the PR description; pictures go up through GitHub's drag-and-drop store; hidden digests find a note already there.
- [Basic mode](basic-mode.md): a PR with no tour opens as a basic tour with no AI; the viewer never switches to a ready guided tour by itself; one screen per file; read ticks carry to the guided tour; the two kinds are separate files.
- [Local review](local-review.md): review the branch plus uncommitted files like a PR; comments as tasks for the agent in the folder; a never-pushed snapshot ref; Changed on disk and Update; Drop review and ref clean-up; Move to PR; no fake PR URL.
- [Review UX](review-ux.md): the shortcuts table, palette actions, gap row, start page and finish, the re-review end, toasts, overlays that leave, Settings as a sheet, the Primary and Secondary send actions, the PR status chip with checks and auto-merge, copyable text and accessibility roles.
- [Keys and the focused change](keys-and-focus.md): keys changeable in `[keys]` with one bad line skipped, key scopes, the focused change moved with Tab and the arrows, `[` `]` and `more_lines`, and piece labels hidden per file by a rule.
- [Back and Forward](back-forward.md): the mouse side buttons and `Cmd+[` / `Cmd+]`; every change of screen and every jump to another line is a visit; Back restores the screen and the code line at the top; the history survives a re-pin and not a PR switch.
- [Comments list](comments-list.md): the `C` sheet that lists every thread in reading order and goes to one, and the record that keeps a thread on the step it was written on.

- [Definitions on hover](definitions-on-hover.md): the Definition card on a name in a Rust, PHP, TypeScript, Python or Go diff line; language servers first, downloaded and pinned by the app and opted into per codebase, with a tree-sitter lookup by name as the fallback; the server checkout that runs no hooks; the code pane beside the lists.

- [Visual design rules](visual-design.md): radii, edges, spacing, border or ground, accent and text rules; a title bar that never clips; one scrollbar and drag; the PR switcher grouped by repo; sidebar stations.

- [Floating panels](floating-panels.md): `overlay::popover` and its siblings as the one way to float a panel, and the clippy rule against a bare `gpui::deferred` (#133).
- [Blade highlighting](blade-highlighting.md): `*.blade.php` coloured from a scan of Blade parts plus the HTML and PHP grammars, since no Blade grammar exists for tree-sitter 0.27.
