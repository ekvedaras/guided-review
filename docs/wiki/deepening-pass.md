# Deepening pass

2026-11-12. Commits `535e9eb` to `70804ab` on the `deepen-architecture` branch (`git log --oneline f9d9e8d..70804ab`).

An architecture review found decision logic in `src/app/` (gpui, no window tests) that belonged in `src/viewer/` (window-free, tested through the fakes in `tests/it/support/fake_ports.rs`). Seven candidates moved it behind small viewer interfaces, one at a time, each behaviour-preserving and tested through the new interface. The reason is the same for all seven: a rule the app keeps cannot be tested, and a rule spread over the session, the layout and a component is changed in one place and forgotten in another.

## The seven candidates

1. **One change gate, `SavedState`** (`535e9eb`, `faa97a2`, `5abb20e`). Every change of the saved review state goes through `src/viewer/saved_state.rs`: `change` for the reviewer's actions (refused while a re-pin runs), `type_in` for keys (saved by the typing save), `record` for outcomes from GitHub or an agent (made always, only the save refused while re-pinning). Before, each `Review` method checked the re-pin and saved by itself, and some forgot. Display options are not saved, so they are reached through `display_options_mut` and are no part of the gate.
2. **One `Problems` value** (`f0629f8`, `635fb82`). The failures the reviewer must know about are one `Problems` keyed by `ProblemKind`, whose doc on each variant says what clears it, instead of eleven fields on `Review`. A new failure is a new variant. A failed Show agent and a tour that could not be read again are problems too.
3. **`CommentDesk` owns the text boxes** (`617b757`, `3605f70`, `6bfabe2`, `ba686cf`, `63d8df7`). A draft, a reply, an edit and the finish body are one `TextBox` with one way to open, type in, leave and give up; whether a box composes, sends or keeps a problem is the desk's, which decides what each send outcome does to its box; one `open_comment_box(CommentGesture)` opens a box from a drag, a picture's button or an Ask answer. Before, the session and `RowFacts` kept copies of that state.
4. **The kept `Page`** (`351c80d`, `1da820a`, `ee15269`). The viewer lays out the page of the open screen once per change and keeps it beside `ReviewCore`; any `DerefMut` drops it, so it cannot go stale. Selection, Ask place, suggestion and picture queries read one page instead of building the step again, and the app keeps only list keys, splicing and the summary's markdown.
5. **The work agenda** (`a65322f`). `Review::due_work(now)` gives the off-thread work due now (reads of GitHub and the clone, the viewed sync, queued comments, seen marks, hand-off delivery), `Review::land` takes each outcome in and makes due what follows. Which work waits, is dropped or replaces the one running is the agenda's, so the session lost its single-flight flags, eleven task fields and `SyncState`, and tests drive the same loop with `drive_until_idle`.
6. **`Intent` and `Effect`: one `decide`** (`f96632e`, `fc3d427`, `c1adc57`). What a key, button or palette action does is `Review::decide(Intent, WindowMoment) -> Effect`, with the refusals while the PR reopens and while Settings is open in `Intent::refusal`; the layout carries the effect out in one `act`. The read rule of going on and the scroll script's step into the next screen are the viewer's too.
7. **The Ask desk** (`70804ab`). `AskDesk` in `src/viewer/ask_desk.rs`, owned by `Review`, holds the Asks and the `AgentPool`: which place the Ask panel is open on, when opening a place asks its empty draft again, which processes run, the restart of a process that died before it took a question and then `QUESTION_NOT_SENT`, what each process event does, and what became of an Ask handed to the reviewer's agent. The page reads the asked lines of its screen from it, so `set_asked_lines`, `asks_changed` and the `asked_lines_of` callback are gone. `Review::change_asks` drops the page only when those lines change, since an answer streams in a line at a time. `AskPanel` keeps drawing, focus and the worker threads, behind the `AskProcesses` port. Asks are still saved by `Asks` through `AskStore`, not by the `SavedState` gate, as before: the gate saves only the viewer's sections, and the decision in [agent runs](agent-runs.md) that Save in Settings waits for no Ask in flight is unchanged.

## Open behaviour questions

Each pass kept the behaviour it found, even where it looked wrong. These are for the maintainer to decide:

- (a) The forward key ticks the step it leaves only after the step's end was seen; the footer's Mark as read and go on always ticks (`f96632e`, a test names the difference).
- (b) The refusals while the PR reopens are not consistent: the palette's Hide/Show whitespace, Ask about step, Finish review, Open on GitHub, Restart and the PR switcher still act. Settings open does not block the shortcuts sheet, though [review UX](review-ux.md) says it waits.
- (c) During a re-pin, `open_reply` and the `discard_*` actions change a box in memory through `record`, and the reload undoes it.
- (d) A sent or queued comment stops composing even when another box is composing. Leaving a draft also drops a queued comment at the same place. A refused-drag notice stays after a picture's comment box opens. A problem saved after a failed save stays hidden and comes back if a box opens again at that place.
- (e) An Ask-agent comment sent later from the queue does not start a delivery until the next trigger.
- (f) `switch_failed` and `tour_not_refreshed` are never cleared on purpose: a successful switch or refresh replaces the review.
- (g) A failed Show agent now lists in the problems list and posts a toast that stays until dismissed.
